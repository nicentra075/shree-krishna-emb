# Demo Data — what it creates & how to test

Generated by [dummy_data_seeder.dart](../../shree_krishna_emb_admin/lib/core/dev/dummy_data_seeder.dart), triggered from **Admin → Settings → Demo Data**. Idempotent: re-running overwrites the same docs (fixed ids), never duplicates.

## Prerequisite (one time)
Deploy the Firestore rules so both apps can read/write the seeded data:
```bash
firebase deploy --only firestore:rules
```
You must be signed into the **admin app as an admin** (e.g. `nic@gmail.com`) — all writes rely on the admin role.

## What "Generate" creates

### 1. Two demo accounts  (password for both: `test123456`)
| Email | Role | Notes |
| --- | --- | --- |
| `dummy.user@shreekrishna.test` | `user` | userId 9001 |
| `dummy.designer@shreekrishna.test` | `designer` | userId 9002, **isAuthorisedSeller: true**, store = "Krishna Embroidery Studio" (+ image + description) |

If an account already exists it is **not duplicated** — the seeder signs in with the demo password to re-create only the profile doc.
> The designer is an **authorised seller**, so it appears in the Home "Authorised Sellers" row.

### 2. Catalog — 3 collections → categories → designs
| Collection (id) | Categories | Designs |
| --- | --- | --- |
| Bridal Collection (`seed_bridal`) | Saree, Lehenga, Blouse | 3 each |
| Festive Collection (`seed_festive`) | Kurti, Dupatta, Sherwani | 3 each |
| Casual Collection (`seed_casual`) | T-Shirt, Cap, Tote Bag | 3 each |

**27 designs total.** Each design has full data: name, code, **2 images**, author "Krishna Embroidery Studio", description, price, discount, **finalPrice**, color/needle count, format (DST/PES), stitch count, height, width, `status: active`, and a descending `popularity` (so "Trending" sorts meaningfully).
- **Design #1 in every category is FREE** (price 0); #2 and #3 are priced (#3 has a ₹100 discount).
- Images are random **`picsum.photos`** photos (real images, not literally embroidery — swap the `_img()` URLs in the seeder if you have real ones).

### 3. Home layout (`config/homeFeed`) — 4 sections
1. **Home Banner** — 3 banners (image + label + title), each links to a collection.
2. **Authorised Sellers** (horizontal) — View All → all sellers.
3. **Trending Designs** (horizontal, sorted by popularity) — View All → `designs?sort=popularity`.
4. **New Collections** (grid) — View All → all collections.

## How to test

### A. Generate
1. Admin app → **Settings** → **Demo Data** → **Generate** → confirm.
2. Watch the progress toasts → ends with **"Demo data generated"**.

### B. Verify in the Admin panel
- **Design Store → Collections** → 3 collections.
- **→ Categories** → pick a collection → its categories.
- **→ Designs** → 27 designs (search/sort work; one free per category).
- **→ Home Layout** → 4 sections (drag to reorder, toggle, edit, Save).

### C. Verify in the User app
1. **Hot-restart** the user app (or pull-to-refresh Home — the feed is Hive-cached).
2. Home shows: **banner carousel → Authorised Sellers (Krishna Embroidery Studio) → Trending Designs → New Collections**.
3. Tap a **design** → detail screen (image gallery, price/final price or "Free", specs). Opening it adds to **Recently Viewed** (local).
4. Tap a section's **View All** → paginated list. Tap a **collection** → its designs.
5. (Optional) Log in with `dummy.user@shreekrishna.test` / `dummy.designer@shreekrishna.test` (`test123456`).

> If Home looks stale after (re)generating, **pull down to refresh** — the resolved feed is cached for up to 6h.

### D. Re-configure (optional)
In **Design Store → Home Layout** add/remove/reorder sections (e.g. add **Recently Viewed**, or a designs row filtered to one collection), **Save**, then pull-to-refresh the user app.

## "Remove" (clear)
Admin → **Settings → Demo Data → Remove** → confirm. Deletes:
- the seeded **collections / categories / designs**,
- the **home layout** config (`config/homeFeed`),
- the demo **profile docs**.

**Not removed:** the two demo **Firebase Auth accounts** (the client SDK can't delete other users). Remove them manually if needed: Firebase console → **Authentication** → delete `dummy.user@shreekrishna.test` and `dummy.designer@shreekrishna.test`.

After Remove, the user-app Home will be empty (no config) until you Generate again.

## Troubleshooting
| Symptom | Fix |
| --- | --- |
| "Permission denied" during Generate | Deploy rules; ensure you're signed in as an **admin**. |
| Home empty after Generate | **Pull-to-refresh** the user-app Home (Hive cache / version). |
| Sellers row missing | The designer account must have `isAuthorisedSeller: true` — re-run Generate. |
| Images broken | `picsum.photos` needs network; or replace `_img()` URLs with your own. |
| Generate failed midway | It's idempotent — just run **Generate** again. |
